# 차슐랭 시연 시나리오 (확정판, 2026-11-05)

> 이 문서가 시연의 기준이다. 여기 적힌 순서대로 누르고 스크립트를 돌리면 그대로 동작해야 한다(2026-11-05 장호연 결정, 에뮬레이터 + 실제 서버 시연 데이터 모드로 처음부터 끝까지 확인함).
> 동작이 다르면 앱 버그다. 시나리오를 바꾸지 말고 고친다.

## 0. 준비 (시연 전 한 번)

| # | 할 일 | 확인 |
|---|---|---|
| 1 | Pleos 에뮬레이터 실행, 차슐랭 **debug 빌드** 설치(`./gradlew installDebug`). 제출 release도 같은 흐름·같은 판정 기준이다(아래 "빌드 메모") | 독에 앱 아이콘 2개(왼쪽 차슐랭) |
| 2 | `local.properties`에 Supabase 공개 키 2줄(`supabase-public.properties` 복사). 없으면 Fake 저장소로 돌아가며 흐름은 같다 | 앱 로그 `SupabaseSync: connected` |
| 3 | Git Bash에서 `bash tools/vconsole.sh up` (하트비트 시작). **파이프(`\| tail`)로 받지 말 것** | `준비 완료` |
| 4 | `bash tools/demo-charge.sh reset` → 기어 P, 차속 0, 충전구 닫힘, SoC 40% | 콘솔 200 ×4 |
| 5 | 처음 보여 줄 때는 앱 데이터를 지운다: `adb shell pm clear --user 10 com.hyundaiapp.chachelin` | 앱을 켜면 S7 동의 화면 |
| 6 | 앱을 켜고 **5초 기다린 뒤** 스크립트를 돌린다(신호 연결 시간) | S1에 충전소 10곳 |

스크립트 출력 창은 녹화 화면 밖에 둔다.

## 1. 시연 순서 (약 3분)

시연 충전소는 **시흥동 주민센터 (시연)** 하나다. 에뮬레이터 위치가 판교 시흥동에 고정이라 충전은 항상 이곳에서 일어난다(목록에서 0.0 km). 다른 충전소를 골라 길안내를 보여 줘도 되지만, 충전 장면은 시흥동 주민센터로 나온다.

| 단계 | 발표자가 하는 것 | 스크립트·콘솔 | 화면 | 말할 것 |
|---|---|---|---|---|
| 1 | 앱 실행 | — | **S7 첫 실행 동의**: 위치정보 [동의], 개인정보 [동의], 내 차 "아이오닉 5", [시작하기] | 동의 버튼을 누른 것만 동의로 본다. 차종은 배터리 용량(계산 평균 kW)용 |
| 2 | — | — | **S1 근처 충전소** 10곳이 차슐랭 점수순. 카드마다 점수·거리·계산 평균 kW·인증 수, 실패가 있으면 "7일 실패 N회" | 점수 = 평균 별점 × (1 − 30일 실패율). 시드 데이터(판교 3km) |
| 3 | 목록을 아래로 넘겨 **시흥동 주민센터 (0.0 km)** 누르기 | — | **S2 상세**: 점수, 인증 충전 수, 계산 평균, 7일 실패, 최근 실패 시각, 별점 분포, 태그 | 실패 기록은 운전자가 신고한 게 아니라 차가 기록한 것 |
| 4 | [길안내] → 팝업 [길안내 시작] | — | 차량 내비가 앞으로 나오며 경로 표시 | NaviHelper `requestRoute`. 기존 경로를 덮어쓰므로 확인 팝업 |
| 5 | 독의 **차슐랭 아이콘**을 눌러 앱으로 돌아오기 | — | S2 그대로 | (도착했다고 설명) |
| 6 | — | `bash tools/demo-charge.sh success` | 2초 뒤 **S3 충전 기록 중**이 자동으로 뜬다. SoC 40→50→60→70→80, 경과 시간·계산 평균이 오른다(약 15초) | SoC는 콘솔 주입, 시간·kW는 시연 배속 ×120 |
| 7 | — | (스크립트가 충전구를 닫음) | 1~2초 뒤 **S4 충전 완료**: "인증 충전 완료 · 시흥동 주민센터 · 40% → 80% · 35분 · 계산 평균 53 kW" + 별 5개 + 태그 6개 | ΔSoC·시간·거리 조건을 통과한 인증 충전만 리뷰할 수 있다 |
| 8 | 별 5개 → "빠름"·"대기 없음" → [평가 보내기]. 별을 누르면 "5점 선택" 줄이 생겨 태그가 조금 아래로 밀리니 **태그 위치를 보고** 누른다(11-07 리허설에서 빗나감) | — | **S2로 돌아오며 새로 조회**: 인증 충전 +1, 5점 +1 | 3초 리뷰. 서버 점수 뷰가 바로 다시 계산됨 |
| 9 | — | `bash tools/demo-charge.sh fail` | S3이 뜨고 SoC가 40%에 머문다(35초) → 충전구 닫힘 → **S5 "충전 실패를 기록했어요"** [실패 기록 취소] [닫기] | 운전자가 아무것도 안 해도 실패가 기록된다. 원인은 단정하지 않는다 |
| 10 | [닫기] | — | S2: 7일 실패 +1, 최근 실패에 지금 시각(서버가 시간 단위로만 줘서 정각으로 보임 — 20:34면 "20:00") | 다른 운전자에게 "최근 실패 1회"로 보인다 |
| 11 | [뒤로] → S1 오른쪽 위 시계 아이콘 | — | **S6 내 충전 기록**: 방금 인증 1건·실패 1건 | (선택) [동의 철회]로 즉시 삭제도 보여 줄 수 있다 |

## 4. PT·영상에서 밝힐 것

- SoC는 에뮬레이터 콘솔로 주입한 값이다(에뮬레이터는 충전 중 SoC가 오르지 않음).
- 화면의 충전 시간·kW는 시연 배속 ×120을 곱한 값이고, 판정 기준도 시연용(인증 10초·실패 30초)이다. 실제 기준은 PRD 5.3(인증 3분·실패 2분).
- 충전소와 다른 차량 기록은 시드 데이터(판교 반경 3km 10곳)다.

## 5. 빌드 메모

- 시작 화면: 동의 전 S7, 동의 후 S1. debug·release 모두 같다(11-05 장호연 결정. 전에는 debug가 개발 메뉴에서 시작했음).
- 개발 메뉴(debug만): **S1 제목 "근처 충전소"를 길게 누르면** 열린다. 화면에는 보이지 않는다.
- 판정 기준: `BuildConfig.DEMO_RULES`가 true면 `ChargeRules.DEMO`. debug는 항상 true, release는 `supabase.demo`(기본 true, 시연 데이터 모드)와 같이 간다. 실제 기준으로 빌드하려면 `local.properties`에 `supabase.demo=false`.
- 제출 release APK: `bash tools/build-release.sh` → `apk/SamgakGorae_Chachelin_release.apk`. 심사위원이 직접 눌러도 위 시나리오가 그대로 된다(스크립트 대신 Virtual Console 웹 화면에서 충전구·SoC를 바꾸면 됨).
